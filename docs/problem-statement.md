# Problem statement

## Who

Software engineers (frontend, backend, full-stack, and related) who are growing toward a target role — via job descriptions, interviews, or a self-chosen level (e.g. Staff Frontend).

## Problem

Learning is scattered across books, videos, courses, practice platforms, and side projects. Progress is hard to see, hard to revise on purpose, and hard to show on a resume or in an interview. Job descriptions expose skill gaps, but there is no clear path from “gap” → learn → practice → demonstrable proof.

## What “better” looks like

- Log learning in under a minute and still get meaningful weekly progress / gaps / priorities.
- Start from a resume + JD, a JD alone, or a manually entered target role.
- See matches and gaps, then get a proposed roadmap the user can approve.
- Move skills through progress states: Studied → Practiced → Applied → Demonstrated.
- Build small practical projects that close gaps and can be shown publicly.

## v1 scope

**In**

- Audience: software engineers only.
- Career Intelligence (role/skill gap analysis).
- Adaptive learning roadmap (AI proposes, user approves).
- Guided learning + practical mini-projects + progress tracking.
- Multiple independent roadmaps per user.

**Out (for now)**

- Other professions.
- Automatic scraping of every learning site.
- Job application tracker / LinkedIn posting (separate product later).
- Paying cloud LLMs as the default (prefer free/local first when we add AI).

## Success criteria (discovery)

- A new user can understand the product from the README + this doc.
- Work can be broken into tickets that map to the four capabilities.
- Feature implementation starts only after this framing is accepted.

## Assumptions

- Users will enter learning data (at least at first); integrations come later.
- Stack and AI choices stay free-first / local-friendly when implementation starts.
